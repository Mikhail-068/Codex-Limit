# Архитектура Codex Gauge

Дата сверки с исходниками: 2026-09-04. Снимок подготовлен для первого коммита проекта и включает текущее рабочее дерево. Ревизию снимка после коммита можно получить командой `git log -1 --format=%H -- docs/architecture/README.md`.

## Реализовано

Нативное WPF-приложение .NET 8 для Windows. Точка входа `src/CodexGauge/Program.cs` создаёт единственный экземпляр через именованный mutex. Windows Forms используется только для значка и меню трея. DPI задаётся WPF-манифестом `src/CodexGauge/app.manifest`.

Текущий дизайн — указатель топлива со шкалой долей бака. `GaugeFace.FuelZone` задаёт границы: <10 красный, 10–20 включительно жёлтый, >20 зелёный. Обычный размер 200 единиц WPF. `Preferences.Load` переносит настройки первой версии: один раз делит старый размер на 1,5 и устанавливает `SizeVersion=1`; сохранение выполняется прежним механизмом. Новые настройки уже используют уменьшенные размеры. Это локальное изменение представления и формата настроек; компоненты и потоки схемы не изменились, перегенерация Archify не требуется.

| Компонент схемы | Реализация и ответственность |
| --- | --- |
| `gauge-window` | `src/CodexGauge/GaugeFace.cs`: векторный циферблат, стрелка, подписи, анимация; `GaugeWindow.cs`: прозрачное окно и управление мышью |
| `quota-model` | `GaugeWindow.cs`: состояние, выбор окна, свежесть, ошибки; `Quota.cs`: нормализация ответа и вычисление остатка |
| `rpc-client` | `CodexClient.cs`: поиск exe, собственный процесс App Server, JSON-RPC по stdio, сопоставление ответов по id, тайм-аут и переподключение; таймер принадлежит `GaugeWindow.cs` |
| `codex-server` | Установленный пользователем Codex. Его процесс обслуживает протокол и использует штатную авторизацию. Монитор завершает только собственный дочерний процесс |
| `openai-service` | Внешний сервис лимитов Codex, доступный через App Server; внутренняя реализация сервиса не проверялась |
| `preferences` | `Preferences.cs`: локальный JSON в `%LOCALAPPDATA%/CodexGauge/settings.json`; вызывается контроллером окна |

## Поток данных и интерфейсы

1. Приложение запускает `codex app-server --listen stdio://` без консольного окна.
2. `initialize` с `clientInfo` → ответ → уведомление `initialized`.
3. При запуске и далее каждые 10 секунд `account/rateLimits/read` возвращает снимок лимитов. `account/rateLimits/updated` также инициирует чтение; запросы не перекрываются.
4. `QuotaParser` предпочитает `rateLimitsByLimitId` перед `rateLimits`. Остаток = `clamp(100 − usedPercent, 0, 100)`. Неизвестный процент исключается из доступных показаний.
5. Выбранное окно лимита → `GaugeFace`, подсказка и трей. По умолчанию `codex` с `windowDurationMins == 10080`; ключ сочетает bucket и период, поэтому перенос между primary и secondary не сбрасывает выбор.
6. Ошибка транспорта сохраняет старое значение с явной отметкой. Ошибка авторизации очищает значения. Нет успешного ответа 25 секунд или наступила дата сброса — показания не считаются свежими. Повторная проверка не вычисляет новый лимит самостоятельно.
7. Вход запускается только действием пользователя через меню: `account/login/start` с `type: chatgpt`, официальный адрес открывается системным браузером. Токены обрабатывает Codex.

## Границы и ограничения

- Это локальный монитор снимков сервиса, а не измеритель локальной скорости расхода токенов.
- Интервал — 10 секунд; при запросе, не завершившемся к тику, новый запрос пропускается. На каждый RPC действует тайм-аут 8 секунд.
- Отдельный процесс App Server не обязан получать уведомления о каждом действии в других клиентах. Основной механизм — периодический опрос.
- Чтение лимитов не создаёт task/turn и не вызывает модель. Код не читает и не копирует auth.json, не пишет токены или исходные ответы авторизации в журнал.
- На диск пишутся только настройки. Диагностические режимы по явному запуску сохраняют очищенные отчёты и изображения в заданное место.
- Нужны .NET 8 Desktop Runtime и Codex, авторизованный через ChatGPT. В изоляции агента авторизация может быть недоступна, что было подтверждено сравнением статуса входа.
- Нет автозагрузки, установщика, автоматического обновления и публикации. Эти возможности не реализованы.
- При смене/отключении мониторов восстановление позиции проверяет пересечение с виртуальным рабочим столом; сложная геометрия с промежутками между мониторами требует ручной проверки.
